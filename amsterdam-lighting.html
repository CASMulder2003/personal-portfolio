Mapping Amsterdam’s street lighting

I built an interactive web map to explore OpenStreetMap road and lighting data across Amsterdam. I processed the layers in R and developed a day/night display with a road-length statistic that updates as users pan and zoom.

The map highlights roads recorded as lit. Its percentage describes the selected mapped road length, so data coverage and the area in view affect the result. It does not measure physical illumination.

What “included” means: the original calculation selects road features whose bounding boxes overlap the current map view, then counts each feature’s full length. It does not clip road segments at the viewport edge. Zooming changes the selection, so this is a view-dependent indicator, not a fixed neighbourhood score.

Map development

Synchronising maps
and updating the statistic

The original React application uses two synchronised maps: a daytime base and a night layer with highlighted roads. Fading between them preserves the reader’s position. This followed experiments with other map arrangements that produced camera or transition problems.

I prepared the geographic layers in R, brought them into the browser and connected map movement to the summary. Precomputing each road’s length and bounds lets the statistic update without repeating all geometry calculations during navigation.

What the lighting data can tell us

OpenStreetMap lighting tags are contributed by volunteers, and coverage is uneven. A missing tag does not establish that a road is unlit. The project maps recorded lighting status. It does not measure brightness, lamp condition or pedestrian safety.

Data, calculation
and limitations

How the percentage is calculated +

Lengths are calculated from road coordinates using great-circle distances. A road counts as lit when its own tag is lit=yes, or its geometry matches a feature in the project’s lighting dataset. The numerator sums those road lengths. The denominator sums all road lengths selected by the viewport bounding-box test. The displayed percentage is rounded to the nearest whole number.

The portfolio map uses the same selection and status rules. Its day/night display is a change of visual emphasis, not a time-series or simulation of illumination.

Source, ownership and development support +

Individual CASA0028 coursework, submitted in February 2026. The source code documents AI assistance with the statistics utilities and map transitions.
